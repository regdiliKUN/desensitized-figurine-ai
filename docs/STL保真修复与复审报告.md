## 一、两条链路的严格切分

| | 图像生成链路（用户认为"效果尚可"） | STL 生成链路（本次故障域） |
|---|---|---|
| 入口 | `fig.py img / i2i / edit_image` → ComfyUI | `fig.py model / image_print / all` |
| 中间产物 | `ComfyUI/output/*.png` | 背景分离 → 正方形白底 → 3D 重建 → `.glb` |
| 出口 | PNG | `convert_3d.py`：平滑/减面/修复/扶正/缩放/底座/抽壳 → `.stl/.3mf` |
| 评估 | `check_background_cleanliness`、`check_front_view`（**只在此链路调用**） | `print_diagnostic`（只有水密/壁厚/尺寸/锐边/朝向，**无相似度**） |

**断点就发生在两条链路的交界**：出图链路的判据从不作用于 3D 输入；GLB 生成后，参考图路径没有随模型传给 `convert_3d.py`，STL 阶段连"和谁比"都不知道。

## 二、问题定位与依据（根因 / 表象）

### 根因 1：3D 输入门禁缺失，且不合格输入被放行（输入处理 + 评估）

- 参考原图是**沙发上的躺姿角色 + 室内窗影场景**（880×1184）。实测：
  - `check_front_view` 左右不对称度 **0.1763 > 0.12**（隔离后正方形图 0.1499）；
  - `check_background_cleanliness` 低饱和灰区 **30.6% > 30%**；
  - rembg 前景占比 **45.4%**，掩膜把沙发与角色连成一块，宽高比 0.7627。
- 这两个检查只出现在 `cmd_img` / `cmd_img2img`；`cmd_model` / `cmd_image_print` / `cmd_all` 的 3D 路径**一次都没调用**。
- 依据：修改前 `fig.py` 第 747、1384 行是这两个检查的唯一调用点；`cmd_image_print` 直接把用户选的图交给 `cmd_model`，无任何前置判定。
- 后果：单图 3D 重建把整张图（含沙发、窗影、背景板）重建成几何，GLB 包围盒 `[1.911, 1.965, 0.902]` 近似立方体，本质是"场景块"而不是角色。**这是"成品与原图几乎无关"的第一根因，且后处理无法补救。**

### 根因 2：参考图没有跨链路传递（数据传递）

- `cmd_print` 只向 `convert_3d.py` 传模型路径、格式、高度、底座等参数，不传参考图；`_prepare_3d_source` 生成的真实 3D 输入图写在 `tempfile.TemporaryDirectory`，退出即删。
- 依据：`convert_3d.py` 原 `main()` 参数表里没有任何图像类入参；`fig.py cmd_print` 构造的 `cmd` 列表不含图像路径。
- 后果：STL 阶段无法做轮廓/朝向/比例校验，也无法判断自己导出的是不是坏模型。

### 根因 3：两条 3D 输入路径都关闭了关键背景清理（输入处理 / 参数配置）

- `isolate_background()` 文档声明六步清理，但 `_prepare_3d_source`（Meshy）与 `_cmd_model_local`（Hunyuan）**都传** `drop_color_blobs=False, drop_flat_ratio=0`，只剩连通域 + 空洞填充。
- 依据：修改前两处调用参数完全一致且都为上述值；`_iso_fig_edit_...png` 的 alpha 仍保留沙发。
- 后果：背景高饱和色块 / 扁平块被当主体送进重建。

### 根因 4：朝向用"最长包围盒轴 = 身高"的错误启发式（几何重建 / 参数配置）

- `convert_3d.orient_upright()` 按 X/Y/Z 包围盒最大跨度选旋转轴。含背景的场景块近似立方体，最长轴与"身高"无关。
- 依据（同一 GLB，仅改平滑参数，选出的轴不同）：
  - 无平滑：`Y→Z (绕X转-90°)` → `[145.915, 68.846, 150]`
  - Taubin×10：`X→Z (绕Y转90°)` → `[63.629, 145.661, 150]`
  - 历史两份 STL 也分别是 `[63.629,145.661,152.25]` 与 `[42.179,98.105,152.25]`。
- 导入态正面轮廓 IoU 仅 **0.2861~0.3185**，而 24 个立方体朝向里存在 **0.61~0.64** 的正确朝向，说明朝向信息在模型里、只是被丢弃/选错。

### 根因 5：比例、缩放、底座全部基于"含背景的包围盒"（几何重建 / 后处理）

- `--height 150` 按扶正后 Z 跨度整体缩放，把背景板高度当身高；参考宽高比 0.7627，模型 0.97~1.04，误差约 **27%~36%**。
- `add_base_plate()` 用底部 5% 顶点的 `max(XY 跨度)` 定半径、中心硬编码 `[0,0]`，并盲目 `fill_holes()`：
  - 实测旧链路底座半径 **64.76**、厚 4.50，Y 跨度由 68.85 被撑到 **129.52**；底座把背景板焊进成品。
- `cmd_image_print` 对 Meshy 结果**自动强制 `--solidify`**，而项目文档自己记录该操作把锐边从 0.4% 碾到 20%+；`--smooth 10` 再叠加一层平滑。这是"关键特征糊掉"的表象放大器。

### 根因 6：评估环节缺失，坏模型一路绿灯导出（评估）

- `print_diagnostic` 只报水密/壁厚/尺寸/锐边/朝向，没有轮廓 IoU、宽高比误差、参考图来源；`main()` 无论指标多差都会 `m.export(stl)`。
- 依据：三份历史 STL 几何差异巨大，却都以退出码 0 生成。

### 根因 7：导出单位不一致 + 产物命名可覆盖（文件导出 / 可复现性）

- `3mf` 分支对已经按 mm 归一的网格再乘 `unit_scale=1000`，而 STL 不缩放。
- 实测历史 `hq_v2_00001_.3mf` 写 `unit="millimeter"`、顶点 `x=-74797.17`，对应同网格 STL 仅约 150 mm，**差 1000 倍**。
- `--out-prefix` 原先只在 `--solidify` 分支生效，其他情况静默忽略，同目录多次转换互相覆盖。

### 表象（不是根因，勿单独修）

STL 是"平板/一团刺"、面数巨大、锐边多、非水密：这些都是上游"场景被当角色重建 + 朝向/比例算错"的结果；只调平滑、减面、体素重建只会让形状更糊。

## 五、独立复审（严苛）

### 5.1 逐项复查

- **架构**：两链已可清晰切分；新增 `mesh_fidelity.py` 只服务 STL 链，未污染图像生成链。但 `fig.py` 仍是 3400+ 行单体，门禁/落盘/编排散落其中；`control_server.py` 与 `fig.py` 各自维护一份参数白名单，新增字段必须改两处，存在漂移风险。
- **数据流**：断点已闭合（`<GLB>_3d_input.png` + `--ref-image` + 自动发现）。但**仅在成功路径落盘**：若 `wait_done` / `collect_files` 抛错，`_cmd_model_local` 暂存的 `_3d_input_<uuid>.png` 不会被清理，会留下孤儿文件。
- **模块职责**：`mesh_fidelity.py` 同时承担掩膜、评分、几何变换、报告、CLI，职责偏多；`convert_3d.py` 仍混有格式导出与保真评估。当前规模可接受，后续扩展会变脆。
- **精度指标**：只用**单视角 2D 轮廓 IoU + 宽高比**，无侧/背视图、无关键点/五官/服饰特征度量。指标已统一为自归一化（平移缩放不变），并明确区分"导入态/朝向/比例/最终"，未用掩膜迁就坏模型刷分。但 IoU 仍会被"背景块恰好长得像参考"虚高——沙发样本的 0.726 里，相当一部分重合来自**沙发本身**，不等于角色相似度。
- **异常处理**：门禁与相似度不达标均返回 2 且报告先落盘；裁剪超 15% 自动撤销；`--no-fidelity` / `--allow-low-fidelity` / `--allow-bad-3d-input` 提供受控逃生口。缺：参考图不可读时只告警并退回旧启发式，属于静默降级；`repair_watertight` 失败时只打印，不阻断导出。
- **可复现性**：报告 + 8 个单测 + 三个 CLI 已具备；但**没有 run manifest**（seed、ComfyUI 工作流哈希、3D 引擎/权重版本、完整命令行未落盘），跨机器重跑仍依赖口头参数。
- **最终产物**：轮廓/朝向/比例/单位/命名已修；**水密性未修**；角色级特征未恢复。

### 5.2 残留缺陷与风险（按优先级）

**P0-1｜参考原图本身不合格，角色级相似度无法由后处理恢复。**
项目内该角色只有沙发躺姿 + 室内场景图（`fig_edit_cfbf17969f53...` 与 `fig_edit_7a8588044770...` 是同一场景的两个版本），另一张 `源图_分离后.png` 是**不同角色**。现有 GLB 重建的是"沙发 + 人"整块场景，五官、发型、四肢、服饰从未被正确建出；裁剪/对齐只能让**轮廓**贴合，不能凭空造特征。**必须提供同一角色的正面站立、纯白底、无道具参考图重建**，否则"STL 与参考原图一致"在角色特征层面不成立。新门禁已阻止这类输入继续污染产物。

**P0-2｜所有产物非水密，切片会失败。**
端到端 STL 焊接后仍有 **2,926 条边界边 / 7,965 条非流形边**；`repair_watertight` 的 `fill_holes` 对这种非流形拓扑无效。项目自带的 `--solidify` 能水密化但会把表面碾粗（项目文档已记录锐边 0.4%→20%+），与保真目标冲突。注意：直接以 `process=False` 读 STL 会得到"三角形汤"，其 `is_watertight=False` 是格式假象，**评估必须基于焊接后的网格**。这是精度与可打印性之间的显式权衡，当前未决。

**P1-3｜正/背面不可分辨。**
轮廓 IoU 对绕 Z 轴 180° 完全对称，24 朝向里正面与背面得分相同；端到端正交渲染显示的是**背面**（无五官、头发盖脸）。需要额外信号才能定正面，现有掩膜做不到。

**P1-4｜放射状细条伪影（发丝重建）无法用简单几何过滤去除。**
实测面最长边中位数 0.006、最大仅 0.0124（≈2 倍），针状三角形判据完全无法分离；这些细条由大量小三角面串成，需从 3D 重建输入/多视图侧解决，后处理强删会伤主体。

**P1-5｜门禁阈值样本量不足。**
`asym=0.12` 只由"1 张坏图 / 1 张好图"校准， legitimate 的非对称站姿、单侧举物、双马尾偏分都可能被误杀。已提供覆盖参数，但缺批量标定。

**P2-6｜评估仍可能被裁剪机制轻微抬高。**
虽然对外指标用自归一化 IoU，但裁剪本身删掉了参考轮廓外的面；对"参考掩膜含背景"的样本，两者会互相迁就。已用 15% 面数上限兜底，未根治。

**P2-7｜预览脚本取景错误。** `render_views.py` 的透视相机把模型顶部裁掉（本次三个模型均复现），会给出误导性预览；本次验证改用正交相机脚本 `print_ready/_verify/render_front_ortho.py`。该缺陷属于评估链路，不影响 STL 本身。

**P2-8｜可复现性与清理。** 无 run manifest；失败路径遗留孤儿暂存图；`--unit` 已退化为兼容空参；默认不减面导致失败样本 STL 74 MB。均不影响几何正确性。

### 5.3 优先处理顺序

1. 换用同一角色的正面站立纯白底参考图重建（解决 P0-1，其余一切的前提）。
2. 在现有模块内确定水密化策略并把它做成显式、可度量的一步：记录焊接后边界/非流形边数，比较"拓扑补洞 vs 体素水密化"对 IoU 与锐边的损失，给出可配置阈值（P0-2）。
3. 增加正面判定信号与侧/背视图 IoU（P1-3 / 精度指标单视角）。
4. 批量标定门禁阈值，把误杀/漏杀率写进报告（P1-5）。
5. 从 3D 重建输入侧处理细条伪影；修正 `render_views.py` 取景（P1-4 / P2-7）。
6. 补 run manifest、失败路径清理、`--unit` 清理（P2-8）。

## 六、明确结论

1. **图像生成链路不是故障源**：它对背景/姿态已有判据，问题在于这些判据从未进入 3D 链路，且参考图在 GLB→STL 边界被丢弃。
2. **STL 精度失效是 7 个环节叠加的结果**，其中根因是"不合格输入未被拦截 + 参考图未传递 + 朝向/比例/底座全部基于含背景的包围盒 + 无相似度评估"；"平板/刺团/非水密/锐边"是表象。
