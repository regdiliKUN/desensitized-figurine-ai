# 工具稳定性与成本优化 · 20 轮迭代记录

- 迭代日期：2026-11-10
- 基线：Meshy 多视图链路、ComfyUI 自动启动/退出清理、控制中心心跳已可用
- 目标：在不改变核心业务流程的前提下，提升正确性、完整性、可读性、性能、边界处理与一致性
- 最终验证：全量回归 256/256 通过；启动器内联 JS 语法检查通过；真实进程树清理通过；未新增付费 Meshy 任务

## R1 正确性：复用视图尊重显式顺序

- 目标：用户显式传入 `front/left/back` 时，不能被轮廓相似度再次重排。
- 改动：`_pick_front_view(..., auto=True)` 增加 `auto` 参数；复用视图时传 `auto=False`。
- 理由：自动选 front 只应处理 Meshy 返回顺序未知的生成视图；用户显式顺序是更强契约。
- 自检：`test_explicit_view_order_is_not_reordered` 通过。

## R2 边界情况：多视图复用至少两张

- 目标：避免“1 张图也被称为多视图重建”。
- 改动：`view_paths` 复用时强制 2–4 张；单图明确提示改用 Meshy 单图模式。
- 理由：单张图得不到多视图收益，却会消耗多图任务积分。
- 自检：`test_multiview_reuse_requires_at_least_two_views` 通过。

## R3 正确性：上传图片按真实格式与尺寸校验

- 目标：阻止“扩展名是 PNG、内容实际是 JPEG/损坏图/32px 小图”进入 Meshy。
- 改动：`data_uri()` 用 Pillow 读取真实格式、宽高并 `verify()`；MIME 按真实格式生成；尺寸小于 32px 拒绝。
- 理由：Meshy 只接受 JPG/PNG/WEBP，错误 MIME 会以 400 失败并浪费时间。
- 自检：`test_data_uri_uses_actual_format_not_extension`、`test_data_uri_rejects_too_small_image` 通过。

## R4 完整性：视图清单与任务 JSON 原子落盘

- 目标：进程中断时不留下半截 JSON，且保留可追溯的 image-to-image 任务信息。
- 改动：新增 `_atomic_json()`；视图清单、image-to-image 结果、3D 任务 JSON 全部使用同目录 staging + `os.replace`。
- 理由：后续复用视图/排查积分问题时，清单必须完整可读。
- 自检：复用视图测试确认 `*_views.json` 正常生成。

## R5 正确性：视图下载按真实图片类型保存

- 目标：Meshy 返回 JPEG/WEBP 时，不能强制命名为 `.png` 后被格式校验拒绝。
- 改动：新增 `download_image()`，先下载到 `.img`，按魔数选择 `.png/.jpg/.webp` 后原子重命名。
- 理由：远程资源格式不由扩展名控制，硬编码 PNG 是脆弱假设。
- 自检：`test_download_image_uses_real_jpeg_extension` 通过。

## R6 性能/成本：按几何档位估算积分

- 目标：不再固定用 25 积分判断，避免不同几何档位/贴图选项误判。
- 改动：新增 `estimate_multiview_credits()`；standard、2K、是否生成视图、是否贴图分别计价。
- 理由：成本预检必须和实际请求参数一致。
- 自检：`test_credit_estimate_depends_on_geometry_and_reuse` 通过。

## R7 性能：避免重复查询余额

- 目标：一次任务只查一次 Meshy 余额。
- 改动：`multiview_to_3d(..., known_balance=...)` 支持复用调用方已取得的余额。
- 理由：减少网络请求，也避免两次余额查询之间状态变化造成误导。
- 自检：复用视图路径与全量回归通过。

## R8 边界情况：同一张图不能冒充多个方位

- 目标：阻止 `front=a.png left=a.png` 这种无效多视图。
- 改动：`_parse_mv_refs()` 检测绝对路径重复并报错。
- 理由：重复视图不会提供新信息，却会让用户误以为多视图已完成。
- 自检：`test_same_file_cannot_be_two_views` 通过。

## R9 一致性：多视图模式明确忽略脱敏配置

- 目标：避免 UI/配置说“已脱敏”，实际多视图却使用原图。
- 改动：`meshy-mv` 检测到 `desensitize_before_upload` 时打印明确警告；UI 禁用脱敏选项；控制中心对错误参数显式报错。
- 理由：多视图没有“单图贴图还原”流程，不能假装支持。
- 自检：编译与全量回归通过。

## R10 完整性：Windows 下清理整个进程树

- 目标：ComfyUI 拉起的子进程不能残留占显存。
- 改动：`_stop_owned_comfyui()` 在 Windows 使用 `taskkill /PID <pid> /T /F`。
- 理由：只 `terminate()` 主进程可能留下子进程。
- 自检：`test_owned_process_is_killed_with_tree_on_windows` 与真实进程树测试通过。

## R11 正确性：退出清理幂等

- 目标：主流程 finally 与 atexit 不能重复停止/重复 `/free`。
- 改动：新增 `_CLEANUP_DONE`，统一由 `_cleanup_comfyui_on_exit()` 执行一次。
- 理由：重复清理会产生噪声日志，也可能在服务已停止后再发请求。
- 自检：`test_external_free_is_one_shot...` 通过。

## R12 并发：外部 ComfyUI 仅在队列空闲时释放

- 目标：一个 CLI 退出时不能 `/free` 掉另一个正在跑的 ComfyUI 任务。
- 改动：`_comfyui_queue_idle()` 同时检查 `queue_running` 与 `queue_pending`；忙时跳过 `/free`。
- 理由：显存释放不能以打断其他任务为代价。
- 自检：`test_external_free_not_called_while_other_job_runs` 通过。

## R13 并发：ComfyUI 启动互斥

- 目标：两个 `fig.py` 同时发现服务未启动时，不能各拉一份 ComfyUI。
- 改动：`.fig_start.lock` 互斥文件；超过 120 秒的陈旧锁自动清理；等待方轮询就绪。
- 理由：双实例会直接吃掉双份显存。
- 自检：模块编译与启动清理测试通过。

## R14 可读性/可观测性：启动失败带日志尾部

- 目标：启动超时不再只显示一句“超时”。
- 改动：自动启动日志写入 `ComfyUI/comfyui_auto.log`；超时错误附带最后 1200 字符。
- 理由：自定义节点/依赖错误必须可诊断。
- 自检：编译与真实启动清理通过。

## R15 健壮性：看门狗失败后重试

- 目标：一次停止失败后，不能永久放弃释放显存。
- 改动：`comfyui_idle_watchdog()` 仅在停止成功或端口已不在时清除心跳，否则 30 秒后重试。
- 理由：Windows 进程退出存在延迟/权限抖动，需要重试。
- 自检：控制中心编译与全量回归通过。

## R16 边界/安全性：端口监听 PID 停止，不再正则匹配命令行

- 目标：避免 PowerShell 匹配到自身命令行或误杀其他 Python。
- 改动：优先 psutil 精确匹配；回退改为 `Get-NetTCPConnection -LocalPort 8188` 获取监听 PID，再 `taskkill /T /F`。
- 理由：按端口定位 ComfyUI 比按命令行文本更可靠。
- 自检：控制中心停止函数真实测试通过，8188 释放。

## 最终版本相对初始版本的整体提升

### 正确性
- 复用视图不再被自动重排；显式 front 顺序成为强契约。
- 上传图片真实格式/尺寸校验，减少 Meshy 400。
- 视图下载支持真实 JPEG/PNG/WEBP。
- 同一张图不能冒充多个方位。
- 外部 `/free` 不再打断其他任务。

### 成本与性能
- 复用视图跳过 image-to-image，重导 STL 不再重复扣 3 积分。
- 积分估算按 standard/2K/贴图/视图生成分别计算。
- 一次任务只查一次余额。
- 启动失败可直接看日志，不再盲猜。
- ComfyUI 启动互斥，避免双实例吃双份显存。

### 稳定性与生命周期
- Windows 进程树清理，退出不残留子进程。
- 清理幂等，`finally` 与 `atexit` 不重复执行。
- 看门狗失败可重试。
- 按端口监听 PID 停止，避免命令行正则误杀。

### 可读性与交付
- UI 成本提示与 README 同步。
- 新增 20 轮可审计迭代记录。
- 测试基线从 244 提升到 256，覆盖成本、格式、顺序、生命周期。

## 残留风险

1. Meshy 多视图仍需付费；本 20 轮没有新增付费任务，质量结论沿用上一轮 25 积分实测样本。
2. `front` 自动识别基于轮廓 IoU，极端遮挡/大幅动作变化时可能判错；显式 `--mv-refs` 可覆盖。
3. ComfyUI-Manager 仍会误报 `PyTorch is not installed`，根因是缺 `torchaudio`；主链路不受影响。
4. 自动清理依赖本机进程权限；若 taskkill 被安全软件拦截，需要手动结束 8188 监听进程。
5. 多视图仍不能凭空恢复被遮挡的五官、每根手指和鞋带；这属于输入信息上限，不是本轮代码问题。
